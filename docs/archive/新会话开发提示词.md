## 五、开发纪律（必须遵守）

1. **架构优先**：OpenAPI 契约先行；Domain 不 import chi/redis driver/TiDB driver；Provider 差异只进 Adapter，业务层禁止 `if provider == "aily"`
2. **数据库红线**：MySQL 5.7 兼容（无窗口函数/无 JOIN ON 子查询/TEXT JSON 无 DEFAULT）；SQL 显式列；真实查询 EXPLAIN 验证；Worker 领取一律 CAS+Lease
3. **Run 正确性**：队列 at-least-once 由 CAS 吸收重复；每 Token 不落库；SSE 断开≠Run 失败，终态必须经 get_chat_result Final Reconciliation 收敛；流式转轮询必须显式传 `agent_chat_id`（前车之鉴 11）
4. **身份红线**：调用 Aily 自定义智能体必须用户 UAT（目标 agent 拒绝应用身份，实测 10009）；Studio Session 与 Provider 凭据彻底分离；refresh token 只能 AES-256-GCM 落库
5. **Redis 定位**：只做分发/实时/缓存/会话/限流；业务事实数据必须落 TiDB
6. **外部映射不变**：binding.external_resource_id=agent_id；AgentThread.remote_id=session_id（lazy）；Run.external_run_id=agent_chat_id
7. **决策优先级**：目标架构文档 > Aily 官方文档 > 真实联调结论（进度清单）> 当前任务要求 > 现有代码结构 > 记忆
8. **工作优先级**：架构正确性 > 运行可靠性 > 性能 > 可维护性 > 短期开发工作量
9. **不要恢复 Django** 作为备用后端；历史实现只允许从 `docs/archive/django-reference/` 查证；不删库、不删未归档目录、不动 `.env.local`
10. 前端 PC/Mobile 共用同一 React 项目、同一套 API 与 WorkspaceHost，只拆交互布局（DesktopAppShell / MobileAppShell），禁止两个前端工程
11. 改 Go 后端后 `go build/vet/gofmt` + `go test`（涉及时加集成测试）；改前端后 `npx tsc --noEmit` + `vitest`；SSE 等流式路径必须有 `curl -N` 直连冒烟断言（前车之鉴 2）
