## 追加：首页快捷入口左贴边修复（用户实测反馈）

**现象**：常用智能体/最近使用在内容区左贴边，不在对话中心。

**两个根因（都在 CSS 结构，不在逻辑）**
1. `RunChatPanel` 里 `emptyState ?? <div className="chat-empty">…` —— 传了 `emptyState` 就把容器整个替换掉，于是 `.chat-empty` 的 `align-items:center`（横向居中）和 `flex:1`（纵向居中、把输入框推到底部）全丢，`max-width:800px` 的块只能左贴边。
   → **修法（有普适价值）：布局归面板管、调用方只给内容** —— 改成 `<div className="chat-empty">{emptyState ?? 默认内容}</div>`。
2. 卡片网格 `repeat(auto-fill, minmax(200px,1fr))` 恒生成 3 条 1fr 轨道（实测 `246.656px 246.672px 246.672px`），1 张卡只占第 1 列 → 左堆。
   → 改 `repeat(auto-fit, minmax(200px,236px))` + `justify-content:center`：auto-fit 塌陷空轨道，行内居中。

**验证方式（值得复用）**：不靠肉眼，用 Playwright `getBoundingClientRect` 量「容器中心 vs 卡片行中心 vs 分组标题中心」的偏移，并核对快捷入口块与 `.chat-input-wrapper` 的 x/width 是否一致。实测三处偏移均为 0px，块边界与输入框完全对齐。

**教训**：给组件加"自定义内容插槽"时，别把外层布局容器一起让出去；否则调用方要重新实现一遍居中/撑高，且单测（node 环境无 DOM）抓不到，只有真实浏览器量盒模型才看得见。

## 追加：Aily 智能体配置化（用户提问"是不是写死在代码里"）

**实况（回答依据）**：智能体 id 不硬编码，落库在 `catalog_runtime_bindings.external_resource_id`；`AILY_DEFAULT_AGENT_ID` 只是 `bootstrap_runtime_catalog` 的默认值，**运行时从不读取**。原先 `apps/catalog/` 连 admin.py 都没有 → 配置入口只有管理命令；"主智能体"是隐式的 `applications[0]`。

**本次补上**
1. `apps/catalog/admin.py`（新建）：注册 Provider + ApplicationRuntimeBinding（agent id、identity_mode、enabled 可视化编辑，secret_ref 只写环境变量名）
2. `apps/applications/admin.py`：应用页内联「运行时绑定」（新增智能体 = 建应用 + 填 agent_id，不用敲命令）+ 动作「设为主智能体」
3. `Application.is_default_agent` + `Application.set_default_agent()`（事务内保证唯一，因为 TiDB 不支持条件唯一约束 W036；只有 kind=chat 且有 enabled binding 才有资格）+ 迁移 0005
4. `/api/v2/applications` 返回 `is_default_agent`；前端 `resolveDefaultApplication()` 纯函数（有单测）统一首页输入框与 ChatRenderer 的目标；切换器显示「主」标记
5. `bootstrap_runtime_catalog --list`：一眼看出每个应用绑的是哪个 agent、谁没绑定（实测发现 `wechat-article-writer` 无绑定 → 不会出现在工作台）

**关键认知（易错）**：一个 Application 只能绑一个 agent（`unique(application, runtime_type, provider_key)`）→ "一个智能体 = 一个 Application"；并行多个智能体就建多个应用，前端切换器原生支持。切换主智能体不影响历史 Run（Run 落 runtime_snapshot）。

**顺手修的体验毛刺**：首页在目录未加载完就按 Enter 会被静默拒绝 → 现在按钮置灰 + 提示「正在加载智能体…」+ 不清空已输入文字（实测通过）。

**验证**：`manage.py check` 干净、`makemigrations --check` 无漂移、admin 五个页面（应用列表/应用编辑含内联/绑定列表/Provider 列表/绑定新增）全部 200 且无异常（用 `Client(HTTP_HOST='localhost')`，注意 ALLOWED_HOSTS 不接受 testserver）；后端 132 通过/22 失败（22 个仍是存量 GraphFlow）；前端 tsc 0 错误 + vitest 61/61；浏览器实测首页发送落到主智能体 `/chat/creative-chat?conversation=N`。

## 追加：智能体市场「新建 Aily 自定义智能体 / 设默认 / 改头像」

**需求**：智能体市场新建时能建 Aily 自定义智能体、能设默认智能体、能改头像。

**关键判断（先说结论，避免走错方向）**：Aily 官方 OpenAPI **没有「创建智能体」接口**（`飞书aily/自定义智能体` 只有会话/对话/附件/产物/可见性 5 类资源）→ 产品语义只能是「在 Studio 登记一个已有 agent_id 的引用」= 建 `Application` + `ApplicationRuntimeBinding`（同一事务）。智能体本体仍在飞书后台建。

- 架构纪律：`RuntimeAdapter` 加 `display_label`/`resource_id_label`/`resource_id_pattern`/`resource_id_hint` + `build_auth()`；AgentID 形状写死在 Aily 适配器，业务层与前端都只读注册表/接口 → 没有第二处 `if provider == "aily"`

**踩到并修掉两个真实缺陷（都不是"看起来不对"，是功能性坏）**
1. **axios 全局 `Content-Type: application/json` 把 FormData 打成 JSON**：axios 据此判定 JSON 请求 → `formDataToJSON()` 序列化 → multipart body 不出浏览器 → 服务端 `request.FILES` 空。症状：浏览器上传头像稳定 400「请选择头像文件」，而 curl 直传同一文件 200。**同一个坑也一直埋在附件预上传 `uploadAttachment`**（之前只有 curl 验证，UI 从未覆盖）。修法：请求拦截器里对 FormData 删掉该头。
2. 删除智能体时头像文件遗留 MEDIA_ROOT；市场列表漏返回 `is_public` 导致卡片全显示「私有」。

**验证**：后端新增 27 例全过，全量 159 通过/22 失败（仍是存量 GraphFlow）；前端 tsc 0 错误 + vitest 74/74（新增 runApiAgents 13 例）；Playwright 12 步真实浏览器 E2E 全过（建 Aily 智能体 → 上传头像 → 设默认 → 切换器「主」标记 → 还给创作助手 → 删除），截图 `gui-test-screenshots/s1..s10_*.png`；收尾核对 TiDB 回到 2 应用/1 绑定、creative-chat 为默认、media 无残留。
