## CI 实跑验证（提交后，发现并修掉 5 个额外问题）

首次让 backend workflow 真正跑起来后，又暴露并修复了 5 个问题，最终 `run 34804570324 @ d098e4c`
三个 job（check / integration / mysql57）全绿。

- **CI 无法读日志**：仓库需要 admin 才能下载 job 日志；改为让步骤把失败原因写成 `::error` annotation，
  再用 `GET /repos/shilin414/potal/check-runs/<id>/annotations` 读取（无需 token），本次就是靠它定位的
- **`cmd/api -migrate` 不退出**：迁移后会继续 app.Build（CI 没有 TOKEN_ENCRYPTION_KEY → 失败）并起 HTTP server。
  新增 `backend-go/cmd/migrate`（只迁移然后退出），两个 DB job 改用它
- **全新 TiDB 迁移失败（真实产品缺陷）**：`Error 8048 The isolation level 'SERIALIZABLE' is not supported` ——
  golang-migrate 的 mysql 驱动用 SERIALIZABLE 事务写 schema_migrations，dev 库只是恰好已跳过该检查。
  `app.MigrateUp` 现在先 `SELECT VERSION()` 识别 TiDB，再以连接参数带 `tidb_skip_isolation_level_check=1`
- **reaper 重排不再即时（真实语义缺陷，MySQL CI 稳定复现）**：`now + RequeueDelay` 让恢复出的 Run 1s 内不可 claim，
  而 outbox 已唤醒 worker → CAS 失败。改用 `RequeueRunFencedImmediate`（`available_at=CURRENT_TIMESTAMP(3)`）
  + 同事务 `CreateOutboxEvent`；本地未暴露是因为 **dev TiDB 时钟比本机快**，掩盖了时间语义问题
- **测试可移植性**：`UNHEX(schedule_occurrences.run_id)` —— 该列是 `BINARY(16)` 原始字节，TiDB 宽容、
  MySQL 5.7 报 `Error 1411`；改为直接比较原始列
- **CI 门禁自身**：`rhysd/actionlint@v1` 不存在（无浮动大版本 tag，须固定 v1.7.12）；
  runner 自带 shellcheck → `for i in $(seq ...)` 触发 SC2034（改算术循环）。
  本地要复现 runner 的 lint 行为，需自行下载 actionlint + shellcheck 二进制（本机 `go install` 写 module cache 被拒）
- actionlint/shellcheck 本地复现命令：`actionlint .github/workflows/*.yml`，把 shellcheck.exe 放进 PATH 即等价于 runner
