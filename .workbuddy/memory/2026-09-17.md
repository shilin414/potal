- **配置侧全部正常**，不是配置问题：`remote.origin.fetch=+refs/heads/*:refs/remotes/origin/*`、

  `.git` 是实体目录、`--git-dir == --git-common-dir == .git`、`git worktree list` 只有一条 → **不是 linked worktree**。
- **决定性时间证据**（`stat` 的 Birth 字段）：
  - `.git/refs/remotes/origin` 的 Birth = **2026-09-17 08:57:29.777**，而最后一次 push 写 reflog 的时刻是 **08:57:22**
    → **push 压根没写 loose ref**；目录与文件都是 7 秒后人工修复建的（loose ref Birth 08:57:29.855、
    `sed` 重写 packed-refs Birth 08:57:30.392）。
  - `.git/logs/refs/remotes/origin/dev` Birth 09-13 23:29:16，共 **66 条 `update by push`、链无断点**
    → 4 天 66 次 push **每次都写了 reflog、一次都没写出 loose ref**；`packed-refs` 里 `origin/dev` 一直是旧 sha。
  - 对照基线：`creation_agent_studio - 副本` 与 `飞书开放平台文档` 的 `packed-refs` 也只有一行
    `refs/remotes/origin/<branch>`，且**没有** loose ref → **本机 clone 后该 ref 本来就只存在于 packed-refs**。
    （推翻"是不是被 pack-refs 清掉了"的猜想。）
- **机制**（比 PITFALLS 旧结论更精确）：push 的跟踪引用更新 = 建 `dev.lock` → 写 reflog → `rename` 落盘。
  实测**reflog 这步成功、rename 这步失败**，git 回滚时把它自己刚建的 `refs/remotes/origin/` 目录也删掉
  （正是 09-17 记的"mkdir 必须在 push 之后"），而 `transport.c` 的 `update_tracking_ref()` 返回值不影响
  push 退出码 → **表现为"push 成功"**。所以不是"权限整体被拒"（否则 reflog 也写不进去）。
