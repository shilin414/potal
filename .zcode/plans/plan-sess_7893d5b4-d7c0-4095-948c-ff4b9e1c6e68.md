# 定时任务（Schedule Core + 飞书投递）全栈实现计划

## 范围与裁决（依据三份文档交叉结论）
- 以 ARCH 文档为准：本轮实现 **Schedule → Occurrence → Run（复用现有执行引擎）→ Delivery → 飞书 IM** 全链路 + 前端定时任务中心。
- 不引入 Workflow、不恢复 Legacy Job；Scheduler 不调 Aily、不发飞书；后台执行一律用 owner UAT。
- 新建 UI 采用结构化表单 Modal（与 AgentEditorModal 同构），普通用户不接触裸 Cron。
- 现有 Enterprise 自动化 Tab 不动（后端契约本就不存在，属遗留 UI），本轮不迁移。

## M0 冻结的契约决策（文档未闭合处，本次定案）
- 状态枚举：Occurrence `pending→queued→running→succeeded|failed|skipped`；Delivery `pending→sending→succeeded|failed|skipped`；Schedule UI 状态（运行中/已暂停/失败）由 enabled + 最近 occurrence 派生。
- 触发器：`schedule_type ∈ once|daily|weekly|monthly`；新增 `trigger_config` JSON 存结构化配置（time、days_of_week、day_of_month）；`cron_expression` 列保留、仅内部生成。
- 时区存 IANA 名称，默认 Asia/Shanghai；计算用 `robfig/cron/v3` + `time.LoadLocation`。
- monthly 29/30/31 遇短月 **顺延到当月最后一天**；misfire `fire_once|skip`（默认 fire_once，只补最近一个错过的槽）；overlap `skip|queue`（默认 queue，v1 不做 parallel）。
- `execution_window_seconds` 默认 0；deadline = `scheduled_at + execution_window_seconds`，deadline_policy `skip|execute_anyway`（默认 execute_anyway）。
- conversation_policy `new_each_run`（默认）| `reuse`，reuse 时新增 `conversation_id` 列明确复用目标。
- run-now：创建 scheduled_at=now 的真实 Occurrence（走完整链路、受 overlap 约束），更新 last_run_at、不动 next_run_at。
- 删除 Schedule：硬删 schedules + schedule_deliveries，保留 occurrences/runs/delivery_executions 历史。
- Delivery v1：channel=feishu、sender=owner UAT、target=user|chat、content_mode=summary（结果文本截断 + Studio 会话链接）；重试上限 5 次、指数退避 + 抖动、429 按 Retry-After 冷却；`UNIQUE(occurrence_id, schedule_delivery_id)` 保证幂等。
- owner UAT 失效：Run/Delivery 显式失败并落 error_code，不静默降级 TAT，不自动暂停 Schedule（v1 由 UI 展示失败）。

## 后端（backend-go）

### 1. Migration `0006_schedule_automation`（新增 up/down，不改 0001）
- `runs` 加列：`trigger_type varchar(32)`（默认 interactive_user）、`trigger_id bigint null`、`priority varchar(32)`（默认 interactive_user）、`available_at datetime(6) null`；索引 `(status, available_at, priority, created_at)`。
- 新表 `schedules`（ARCH 2253-2279 字段 + trigger_config/conversation_id）、`schedule_occurrences`（`UNIQUE(schedule_id, scheduled_at)`）、`schedule_deliveries`、`delivery_executions`（`UNIQUE(occurrence_id, schedule_delivery_id)`），索引 `(enabled, next_run_at)`。

### 2. sqlc + 领域包
- `db/queries/automation.sql` 新增查询 → `make gen-db`。
- `internal/automation/schedule`：Schedule 域模型、CRUD、next-run 计算（cron v3）、next-runs 预览、enable/disable 语义。
- `internal/automation/scheduler`：到期扫描循环。`ListDueSchedules`（enabled AND next_run_at<=now，批 100，纯 SELECT，MySQL 5.7 兼容，无 SKIP LOCKED）→ 单事务内：插 Occurrence（唯一键兜底，输者跳过）→ overlap/misfire/execution_window 判定 → `new_each_run` 建 Conversation → Message+Run+Outbox（复用 execution.CreateRun 逻辑，为其 `CreateRunInput` 增加 TriggerType/TriggerID/Priority/AvailableAt 并提供事务变体）→ 回写 occurrence.run_id、schedule.last_run_at/next_run_at。
- `internal/delivery`：`DeliveryAdapter` 接口 + `FeishuDeliveryAdapter`（复用 `identity.FeishuClient.SendIMMessage` + owner UAT resolver）；`Dispatcher.OnRunSucceeded`：Run 成功且 trigger_type=scheduled 时单事务建 delivery_executions + outbox（payload provider=feishu_delivery，经现有 Relay 路由到 `queue:feishu_delivery`）；独立 `execution.NewRateLimiter`（GCRA，key `rate/feishu/im`）；Delivery Worker 消费池（XReadGroup + XAutoClaim + CAS，模式对齐 execution.Worker）。挂点：`aily.Executor.finish` 成功终态后经注入的 dispatcher 回调触发。
- `cmd/scheduler` 第四个二进制 + `cmd/worker` 支持 `--provider=feishu_delivery` 时装配投递池；`app.Build` 增加对应装配；Makefile 加 `run-scheduler`。

### 3. OpenAPI + HTTP
- `api/openapi.yaml`（3.0.3）新增：`GET/POST /api/v2/schedules`、`GET/PATCH/DELETE /api/v2/schedules/{id}`、`enable`、`disable`、`run-now`、`GET /{id}/occurrences`、`POST /schedules/preview`（权威 next-runs 预览）→ `make gen-api`。
- `internal/transport/http/schedule_handlers.go`：owner 鉴权（防伪造 owner_user_id）、keyset pagination、字段校验（结构化 trigger、目标选择校验复用 feishu targets 能力）、Cookie Session + CSRF 规则不变。

### 4. 测试与可观测性
- Go 单测：next-run 计算（时区/周/月末顺延/once）、双 Scheduler 竞争唯一 Occurrence、overlap skip/queue、misfire fire_once/skip、投递幂等（同 occurrence 同 target 只一次）、429 退避（假 adapter）。
- telemetry.Metrics 增加 `schedule_trigger_delay_seconds`、`schedule_queue_delay_seconds`、`schedule_delivery_duration_seconds`、`schedule_misfire_total`、`schedule_overlap_skipped_total`、`delivery_failures_total`；日志带 schedule_id/occurrence_id。
